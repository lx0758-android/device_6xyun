# kernel/config-layering Specification

## Purpose

定义 GKI 共享内核配置与板级配置之间的分层边界和书写规则，保证板级功能既不会被静默丢弃，也不会污染共享内核。

## Requirements

### Requirement: GKI 侧只承载平台使能级改动

GKI 配置 MUST 只允许与 SoC 平台使能相关的改动（CPU 架构支持、PCIe 主机控制器、IOMMU）以及串口控制器可用性修复。任何外设驱动 MUST 通过板级配置以模块形式提供。

#### Scenario: 平台使能项位于 GKI

- **WHEN** 检查 GKI 配置中的本地改动
- **THEN** 改动仅涉及 SoC 架构、PCIe 主机控制器、IOMMU 与串口 UART 计数

#### Scenario: 外设驱动不进入 GKI

- **WHEN** 需要启用某外设驱动
- **THEN** 该驱动出现在板级配置中并以模块形式构建，GKI 配置不新增该驱动

### Requirement: 板级可加载能力必须以模块形式声明

板级配置中的三态（tristate）选项 MUST 一律声明为模块。板级没有独立内核镜像，声明为内建的选项会被构建系统静默丢弃。

#### Scenario: 板级选项以模块产出

- **WHEN** 板级配置声明某外设能力
- **THEN** 构建产物中存在对应的模块文件，且该能力在启动后可加载

#### Scenario: 内建声明被拒绝

- **WHEN** 板级配置把普通三态选项声明为内建
- **THEN** 规格判定为不合规，必须在评审阶段修正为模块声明

### Requirement: 复合模块的成员保持内建

会合并为单个模块的复合驱动，其成员选项 MUST 保持内建声明，避免被拆散为多个模块。

#### Scenario: 显示子系统保持单一模块

- **WHEN** 构建板级显示相关驱动
- **THEN** 显示子系统的复合驱动产出为单个模块，未因成员声明为模块而被拆散

### Requirement: 串口控制台在早期启动即可用

内核 MUST 保证串口控制台在早期启动阶段可用，不得因 UART 数量配置为零导致串口控制器注册失败。

#### Scenario: 启动日志从串口输出

- **WHEN** 设备上电启动内核
- **THEN** 串口在早期启动阶段即输出内核日志，不出现串口控制器注册失败

#### Scenario: 配置回归防护

- **WHEN** 更新 GKI 配置
- **THEN** 串口 UART 数量配置不得被重新置零

### Requirement: 媒体所需的内核缓冲堆按模块补充

板级配置 MUST 以模块形式补充媒体栈所需的命名缓冲堆；缺失时媒体编码器无法获取输出缓冲，所有软件编码器统一失败，而显示通路不受影响。

#### Scenario: 编码器获取输出缓冲

- **WHEN** 软件编码器为输出码流申请缓冲
- **THEN** 命名缓冲堆存在且分配成功，编码器正常产出码流

#### Scenario: 缓冲堆缺失时的表现

- **WHEN** 板级配置未提供命名缓冲堆
- **THEN** 编码器输出缓冲申请失败并上报损坏错误，投屏与录屏无法启动，评审阶段必须检出

#### Scenario: 不污染共享内核

- **WHEN** 检查共享内核配置
- **THEN** 该缓冲堆以板级模块形式提供，共享内核仅保留缓冲堆框架本身
