# device/selinux-baseline Specification

## Purpose

定义本阶段的 SELinux 基线：以宽容模式运行这一临时状态、必备的基础类型与设备节点上下文，以及策略的打包方式。

## Requirements

### Requirement: 本阶段以宽容模式运行

系统MUST在内核命令行中声明宽容模式，策略违规只记录不阻断；该状态MUST被明确标注为阶段性妥协。

#### Scenario: 违规不阻断启动

- **WHEN** 某进程访问未被策略允许的资源
- **THEN** 访问被记录到审计日志，系统继续运行

#### Scenario: 收紧作为独立变更

- **WHEN** 后续需要切换到强制模式
- **THEN** 通过独立变更实施，并同步更新本规格

### Requirement: 基础块设备类型映射

策略MUST为启动、设备树叠加、校验、杂项、动态分区与用户数据等块设备建立类型映射，使首阶段挂载可通过策略校验。

#### Scenario: 首阶段识别块设备

- **WHEN** 首阶段按设备节点路径访问分区
- **THEN** 各分区具有对应的块设备类型，不被拒绝访问

### Requirement: 固件与设备节点上下文

策略MUST为厂商固件目录与图形设备节点建立上下文，为后续阶段的硬件服务预留接入点。

#### Scenario: 固件目录可读

- **WHEN** 内核或服务读取厂商固件
- **THEN** 固件目录具有正确的文件上下文

#### Scenario: 设备节点上下文已就绪

- **WHEN** 后续阶段接入图形服务
- **THEN** 图形设备节点已具备类型定义，无需重复定义

### Requirement: 策略与兼容矩阵随镜像打包

构建MUST打包预编译策略与厂商兼容矩阵，保证镜像可独立启动且不依赖编译环境。

#### Scenario: 镜像自包含策略

- **WHEN** 设备使用构建产物启动
- **THEN** 策略从镜像内加载，不需要额外文件

#### Scenario: 兼容矩阵存在于厂商分区

- **WHEN** 检查厂商分区内容
- **THEN** 存在兼容矩阵文件
