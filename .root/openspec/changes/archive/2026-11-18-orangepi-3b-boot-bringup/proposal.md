# Proposal

## Why

第一阶段已经产出完整的镜像集合与分区骨架，但系统里没有任何硬件服务，无法开机。本阶段要在骨架上叠加"最小可用"的硬件服务集合，让设备真正启动到界面，并同时把"阶段性宽容模式"这一临时状态显式记录下来。

## What Changes

- 新增显示栈：合成器、分配器、映射器与软件 GL/Vulkan 回退，使界面能起来。
- 新增音频栈：AIDL 音频服务与音频策略配置，避免 audioserver 反复崩溃。
- 新增最小系统服务集合：电源、健康、密钥（供用户数据加密使用），并明确移除温控、锁屏校验、媒体 DRM 三个非开机必需项。
- **BREAKING**：不提供启动槽位控制服务。单槽位设备上该服务的默认实现启动即崩，且其接口声明会让存储服务的检查点探测永久等待，直接导致用户数据分区无法挂载。
- **BREAKING**：媒体编解码器的服务发现方式切换为 AIDL，否则软件编解码器不可见。
- 补充运行时内存档位参数：不声明时运行时上限回落到极小值，系统服务会在开机阶段因内存耗尽崩溃，并连带触发前置看门狗告警。
- 新增 USB gadget 能力：调试、文件传输与网络共享的配置与初始化脚本。
- 新增各服务所需的最小 SELinux 策略；系统继续以宽容模式运行，收紧留待后续独立变更。

## Capabilities

### New Capabilities

- `device/graphics-stack`：显示合成、缓冲区分配与软件图形回退的组成与属性。
- `device/audio-stack`：音频服务与音频策略配置的组成与约束。
- `device/system-hal-set`：开机必需的最小系统服务集合，以及明确排除的服务。
- `device/usb-gadget`：USB 外设功能的配置、初始化与可切换的组合。
- `device/hal-selinux`：本阶段各服务所需的最小策略与宽容模式边界。

### Modified Capabilities

无。

## Impact

- 产品配置：新增服务包、属性、拷贝文件与 Soong 命名空间。
- 单板配置：显示与音频相关的构建开关。
- 新增文件：音频策略配置、USB 初始化脚本、服务相关的策略文件。
- 面向后续阶段：本阶段只追求"能开机 + 可调试"，不追求硬件加速与真实音视频输出。
