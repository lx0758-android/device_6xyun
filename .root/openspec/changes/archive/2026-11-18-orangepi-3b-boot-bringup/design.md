# Design

## Context

第一阶段已产出可刷写镜像与分区骨架，但产品里没有任何服务。本阶段目标是在不引入真实硬件驱动的前提下让系统完成开机，因此所有服务都选择 AOSP 自带的实现（default / example 变体），并把"阶段性妥协"显式记录。

## Goals / Non-Goals

**Goals:**

- 让系统启动到界面并可通过调试通道访问。
- 服务集合最小化：只保留"缺了就开不了机"的项。
- 每个服务都有明确的取舍理由与退出路径。

**Non-Goals:**

- 不追求 GPU 硬件加速、真实音频输出、硬件编解码。
- 不引入相机、Wi-Fi/BT、传感器等服务。
- 不在本阶段收紧 SELinux。

## Decisions

### D1：全部复用 AOSP 自带服务实现

- 理由：本阶段验证的是"骨架 + 接线"是否正确，自研服务会把问题混在一起。
- 代价：部分实现是示例性质（健康、电源），数据非真实硬件值。
- 备选：先自研最小桩服务——维护成本高且不代表后续实现，放弃。

### D2：显示栈 = DRM 合成器 + minigbm + 软件图形回退

- 内核有显示子系统但没有 GPU 渲染驱动，因此合成器走 DRM/KMS，图形接口走软件实现。
- 分配器三件套（分配库、分配服务、映射器）必须齐备，缺映射器合成器直接退出。
- 代价：软件渲染性能低，仅够验证开机。

### D3：音频栈选择 AIDL 服务 + 新版策略配置

- 音频服务只接受较新版本的策略配置；旧版配置会导致模块注册失败。
- 本阶段无声卡驱动，音频服务只是"占位可用"，避免进程循环崩溃拖慢开机。
- 无采集/播放设备意味着不存在可用的音频数据通路：依赖音频采集的工具（投屏、录屏）必须关闭音频，编码器启动失败属预期。

### D4：最小服务集为电源、健康、密钥

- 电源缺失会让系统服务在初始化时崩溃；健康服务供电池信息；密钥服务是用户数据加密的前提。
- 明确排除：启动槽位控制（单槽位且无校验/无 OTA，默认实现无槽位后缀即崩，其声明还会让存储服务的检查点探测永久阻塞；重启进引导程序由初始化进程直接写引导消息完成）。
- 明确排除：温控（无真实传感器，假数据无意义）、锁屏校验（无锁屏策略）、媒体 DRM（开机无关，属媒体阶段）。

### D5：编解码器发现方式切 AIDL

- 软件编解码器只注册 AIDL 服务，默认发现方式会导致编码器列表为空。
- 该属性同时是后续接入厂商 AIDL 编解码器的前提。
- 软件编解码器在 APEX 进程内，不对外提供编解码器侧输入面；必须同时启用图形缓冲输入面通路，否则为编码器创建输入面时会取到空指针直接崩溃（投屏、录屏必现，已实测复现并有墓碑）。

### D6：USB gadget 用配置子系统在启动阶段建立

- 通过配置子系统预先创建 gadget、功能与配置，再由系统按属性切换组合。
- 组合保留：调试、媒体传输、图片传输、网络共享、音频源、MIDI、附件模式。

### D7：SELinux 保持宽容模式，只补最小标签

- 服务执行文件与图形设备节点必须有正确标签，否则域切换与设备访问会失败。
- 违规只记录不阻断，目的是把"能否开机"与"策略是否完备"解耦。
- 收紧必须走独立变更，并在规格中同步更新。

### D8：显式配置运行时内存档位

- 产品未声明堆参数时，运行时兜底是"起步 4 MiB、上限 16 MiB，增长上限等同上限"；系统服务在这种上限下会在开机阶段频繁回收并最终分配失败崩溃，界面进程也会因回收抖动占满 CPU 连带拖慢系统服务。
- 因此直接在产品里显式声明六个堆参数：增长上限取 2/4 GiB 通用量级，空闲上下限与回收目标比例沿用运行时默认量级，避免大块分配（位图、合成缓冲）反复触发回收。
- 代价：单进程内存水位上升，需与设备实际内存匹配；更高内存档位可再抬高增长上限。

### D9：媒体缓冲堆以板级模块补充

- 媒体编码器的输出码流块由命名缓冲堆（`/dev/dma_heap/system`）分配；共享内核只带缓冲堆框架，具体堆是独立三态选项，必须按板级模块补充并在首阶段随其它模块加载。
- 不能写进共享内核：那会把一个纯设备需求扩散到所有使用该共享内核的产品。
- 代价：多一个模块，启动早期多一次加载；顺序上位于媒体服务启动之前，不影响开机。

## Risks / Trade-offs

- [软件渲染性能低、界面卡顿] → 本阶段只验证功能，性能属 GPU 适配阶段。
- [内存档位与设备实际内存不匹配] → 档位偏低会重现回收抖动，偏高则在低内存板上引发全局回收；先按设备内存规模取下限档位，实测后调整。
- [软件渲染下系统服务仍可能触发前置看门狗] → 先排除内存回收抖动因素，再评估是否属纯渲染性能问题。
- [示例服务的数据不真实] → 记录为已知限制，硬件适配阶段替换。
- [宽容模式掩盖策略缺失] → 规格要求收紧独立立项，避免长期默认化。
- [MTP/PTP 依赖用户数据分区挂载成功] → 若加密或挂载失败，USB 文件传输会不可用，需按日志定位。
- [USB 组合切换依赖控制器实例配置] → 缺少实例会导致 gadget 无法绑定，属首查项。
- [软件编码器输出缓冲获取失败] → 已定位：板级内核未启用命名缓冲堆，媒体栈申请输出缓冲失败并上报损坏错误（C2_CORRUPTED），投屏/录屏无法启动编码；显示走芯片 GEM 分配因而不受影响。修法是按模块补充该缓冲堆，不改共享内核。

## Migration Plan

1. 先接显示栈与最小服务集（决定能否完成开机）。
2. 再接音频与 USB（决定可用性与调试便利）。
3. 补齐策略标签后联调：开机、界面、调试通道、文件传输。
4. 通过后归档，进入真实硬件适配阶段。
