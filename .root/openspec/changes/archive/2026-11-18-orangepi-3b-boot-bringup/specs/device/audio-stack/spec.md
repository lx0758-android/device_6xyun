# Spec Delta

## Purpose

定义最小音频能力的组成与配置要求：服务、策略配置与配套资源缺一不可，使音频服务在尚无真实声卡驱动的环境下也能稳定启动而不拖垮系统。

## ADDED Requirements

### Requirement: 提供音频服务实现

设备 MUST 提供音频硬件服务；缺失任何音频服务会导致音频服务进程反复重启并消耗大量 CPU。

#### Scenario: 音频服务稳定运行

- **WHEN** 系统启动完成
- **THEN** 音频服务处于运行状态，不出现反复重启

#### Scenario: 服务缺失时的表现

- **WHEN** 没有任何音频服务实现
- **THEN** 音频服务进程循环崩溃，系统启动明显变慢，必须在评审阶段被检出

### Requirement: 音频策略配置符合服务所需的版本

设备 MUST 提供与音频服务所解析版本一致的音频策略配置；使用旧版本 schema 会导致配置校验失败、模块无法注册。

#### Scenario: 策略配置被接受

- **WHEN** 音频服务加载策略配置
- **THEN** 配置通过校验，音频模块成功注册

#### Scenario: 版本不匹配时的表现

- **WHEN** 策略配置版本低于服务要求
- **THEN** 服务报"找不到模块"，配置在评审阶段被判定为不合规

### Requirement: 配套音量表与效果配置齐备

设备 MUST 同时提供音量表、音效配置以及蓝牙、USB、次混音等分场景配置，保证音频服务不会因缺少引用文件而启动失败。

#### Scenario: 启动无缺失引用

- **WHEN** 音频服务启动
- **THEN** 所需配置均存在，日志中不出现缺失文件告警

### Requirement: 无采集与播放设备时不提供音频数据通路

设备尚无音频硬件驱动时 MUST NOT 提供可用的音频采集与播放通路；依赖音频采集的调试或投屏工具必须以无音频方式运行，编码器启动失败属预期行为而非缺陷。

#### Scenario: 投屏工具默认开启音频

- **WHEN** 投屏工具请求建立音频采集并启动音频编码器
- **THEN** 编码器启动失败，工具侧报音频流配置错误，视频通路不受影响

#### Scenario: 以无音频方式运行

- **WHEN** 投屏工具以无音频方式运行
- **THEN** 视频画面正常传输，且不产生音频相关错误日志
