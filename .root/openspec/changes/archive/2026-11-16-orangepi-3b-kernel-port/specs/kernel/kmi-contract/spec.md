# Spec Delta

## Purpose

定义板级模块与 GKI 共享内核之间的符号导出契约，保证共享内核裁剪导出符号后板级模块仍可正常链接与加载，并规定符号基线随设备扩展的演进方式。

## ADDED Requirements

### Requirement: 板级符号白名单纳入 GKI 导出集合

板级模块依赖的共享内核符号 MUST 通过一份板级符号白名单声明，并纳入 GKI 的附加导出符号集合，使共享内核裁剪导出符号时保留这些符号。

#### Scenario: 板级模块链接通过

- **WHEN** 构建板级模块
- **THEN** 模块链接阶段不出现符号未定义错误

#### Scenario: 共享内核裁剪保留板级符号

- **WHEN** 检查 GKI 的导出符号集合
- **THEN** 板级白名单中的符号均在其中

### Requirement: 符号白名单与 ABI 基线成对更新

符号白名单与共享内核 ABI 基线 MUST 作为一组变更提交：只更新白名单会导致共享内核 ABI 校验失败，只更新基线会导致板级模块缺少导出符号。

#### Scenario: 白名单新增符号

- **WHEN** 板级模块开始依赖共享内核此前未导出的符号
- **THEN** 白名单与 ABI 基线在同一次变更中一并更新，且共享内核重新构建后导出该符号

#### Scenario: 缺失基线更新被发现

- **WHEN** 仅修改白名单而未更新 ABI 基线
- **THEN** 共享内核的 ABI 校验失败并阻断构建

### Requirement: 符号白名单按厂商归属命名

板级符号白名单 MUST 使用厂商标识命名，而不是按单一设备命名，以支持同一厂商后续新增设备时共用或扩展白名单。

#### Scenario: 新增同厂商设备

- **WHEN** 新增一款同厂商设备并需要额外符号
- **THEN** 可以复用或扩展该厂商白名单，无需另建一套命名

### Requirement: 追踪点符号必须成对出现

涉及内核追踪点的符号 MUST 成对声明，追踪点与其迭代器符号不得单独出现。

#### Scenario: 追踪点符号校验

- **WHEN** 提交白名单变更
- **THEN** 符号校验通过，未出现追踪点与其迭代器不配对导致的失败

### Requirement: 白名单由官方工具生成

符号白名单 MUST 由内核构建体系提供的符号提取工具生成或更新，不得长期依赖人工维护。

#### Scenario: 重新生成白名单

- **WHEN** 板级模块集合发生变化
- **THEN** 使用官方工具从最终模块产物提取符号并更新白名单

#### Scenario: 板级不支持 ABI 基线更新

- **WHEN** 尝试对板级执行 ABI 基线更新
- **THEN** 该操作被判定为不适用，板级只允许更新符号白名单
