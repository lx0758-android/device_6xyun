# Spec Delta

## Purpose

定义 OrangePi-3B 内核以「GKI 共享内核 + 板级模块」形态构建时应满足的产物与目录契约，使下游设备配置只依赖稳定的产物接口，而不依赖内核内部结构。

## ADDED Requirements

### Requirement: 内核镜像由 GKI 共享内核提供

板级构建 MUST 以 GKI 共享内核目标作为基础内核，板级本身 MUST NOT 产出 `vmlinux`、`System.map` 或 `Image`。所有可启动的内核镜像必须来自 GKI 构建。

#### Scenario: 板级构建不产生内核镜像

- **WHEN** 执行板级构建目标
- **THEN** 板级输出中不存在 `Image` / `vmlinux` / `System.map`，且发布目录中的 `Image` 与 GKI 构建产物一致

#### Scenario: 板级改动不影响内核镜像来源

- **WHEN** 仅修改板级配置或板级设备树
- **THEN** 构建仍然复用同一份 GKI 内核镜像，只有板级模块与设备树发生变化

### Requirement: 板级模块清单与实际产物完全一致

板级声明的模块清单 MUST 与本次构建实际生成的模块文件逐一对应，既不能遗漏也不能多报。开启调试构建配置时，看门狗模块 SHALL 被纳入清单。

#### Scenario: 模块清单一致性校验

- **WHEN** 板级构建完成
- **THEN** 声明的每个模块文件都存在于产物中，且产物中没有未声明的板级模块

#### Scenario: 调试构建下的模块差异

- **WHEN** 以调试内核配置构建板级
- **THEN** 看门狗模块从清单中排除，其余模块保持不变

### Requirement: 发布目录提供稳定的下游引用接口

一次构建 MUST 在发布目录中同时提供：GKI 内核镜像、板级设备树、全部板级模块、模块加载清单、首阶段模块镜像。板级模块 MUST NOT 出现在 `system_dlkm` 产物中。

#### Scenario: 发布目录内容完整

- **WHEN** 执行板级发布目标到指定目录
- **THEN** 目录中包含内核镜像、两个板级设备树、全部模块文件、模块加载清单与首阶段模块镜像

#### Scenario: 板级模块不进入 system_dlkm

- **WHEN** 检查发布目录中的 `system_dlkm` 模块清单
- **THEN** 清单只包含 GKI 模块，不包含任何板级模块

### Requirement: 板级设备树随发布目录交付两个板型

板级构建 MUST 产出 v1.1 与 v2.1 两个板型设备树，并按此顺序交付，供引导程序选择。

#### Scenario: 两个板型设备树均存在

- **WHEN** 板级构建完成
- **THEN** 发布目录中存在 v1.1 与 v2.1 两个设备树文件

#### Scenario: 交付顺序固定

- **WHEN** 引导程序按索引选择设备树
- **THEN** 索引 0 对应 v1.1、索引 1 对应 v2.1
